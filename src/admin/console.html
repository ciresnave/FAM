FAM Admin

My agents

Entities in your account, plus any entity another account has shared with you. Status is derived from the connection; availability and queue are what the entity itself declares, and last declared is when it last said something changed — not when it was last seen. An agent with a non-empty queue and an old declaration is either working one long task or stopped mid-task; only its connection tells you which. Doing is the entity's own sentence about its current work, shown with how long ago it last said it — an old summary read as current is worse than none. You may pause or resume your own agents. You cannot set their queue state — only ask FAM to recheck it against messages actually waiting, since nothing out here can see an agent's own task list.

Save this key file now

Shown once and not recoverable. It holds the entity's private key, encrypted with the passkey you just chose — the passkey is not stored and cannot be reset. Without both, the entity cannot authenticate again.

Work nobody is on

Open tasks that are either unowned or whose owner is not connected. These are different problems. Unowned work needs somebody assigned; work whose owner has gone away needs re-queueing, and until it is, it looks assigned to a coordinator and is assigned to nobody.

Two of your agents are in the same place

These agents published the same value for the same key. Sessions sharing a checkout are invisible to each other and can both act on the same files — the usual symptom is two of them claiming the same work.
